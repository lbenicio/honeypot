# Security Policy

## Supported versions

Security fixes are prepared for the current default branch and the latest
published release, if one is available. Older releases are not guaranteed to
receive security updates. Upgrade to the latest release before reporting an
issue when possible.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue or pull
request. Use [GitHub's private vulnerability reporting form](https://github.com/lbenicio/honeypot/security/advisories/new)
when it is enabled for this repository.

If private reporting is unavailable, open a public issue asking the maintainers
for a private reporting channel. Do not include exploit details, credentials,
captured honeypot data, or other sensitive information in that issue.

Include the affected version or commit, relevant configuration, steps to
reproduce the issue, and its potential impact. Remove passwords, tokens, IP
addresses, and other identifying data from logs or examples.

We aim to acknowledge reports within five business days and coordinate a fix
and public disclosure with the reporter. Timelines for investigation and fixes
depend on severity and reproducibility.
